Documentação interna da Storage API

Como integrar, operar e manter a Storage API sem expor tokens nem perder dados.

Ver exemplos Área administrativa

O que esta API faz

A Storage API recebe arquivos autenticados por token de aplicação, salva os arquivos em diretórios isolados por aplicação e registra histórico operacional em SQLite.

Autenticação
Token
Cada aplicação usa seu próprio X-Storage-Token.
Upload máximo
10 MB
Padrão atual. Configurável por MAX_UPLOAD_SIZE.
Banco oficial
SQLite
Aplicações, tokens, usuários admin e histórico ficam no SQLite.

Fluxo recomendado de uso

Use a API desse jeito para evitar exposição indevida do token no frontend.

Fluxo correto
O frontend envia a imagem para o seu backend principal. O backend principal conversa com a Storage API usando o header X-Storage-Token. Assim o token nunca fica exposto no navegador.

1. Upload

Seu backend envia um multipart/form-data com o arquivo.

2. Persistência

A Storage API valida o token, salva no volume Docker e devolve o path relativo.

3. Leitura

Seu backend lê o arquivo usando o token e devolve o binário ou uma URL própria ao frontend.

Atenção sobre o fileUrl
O campo fileUrl retornado no upload aponta para /api/files/read, mas essa rota exige X-Storage-Token. Portanto, esse link não deve ser tratado como URL pública direta. Para imagens públicas, crie uma rota no seu backend principal que injete o token da Storage API e faça o proxy da leitura.

URLs de acesso

Use a URL correta de acordo com o ponto de origem da chamada.

Dentro do Docker Compose http://storage-api:3999
Host local http://127.0.0.1:3999
Base URL configurável A URL usada em respostas pode vir de BASE_URL. No ambiente local atual, o padrão é http://localhost:3999.

Persistência e dados

A Storage API usa volume Docker nomeado para evitar gravação na raiz do projeto Windows.

Volume Docker storage_api_data
Root interno /var/lib/storage-api
Arquivos das aplicações /var/lib/storage-api/storage/apps/{applicationId}
Banco SQLite /var/lib/storage-api/db/store.sqlite
Arquivos SQLite auxiliares store.sqlite-wal e store.sqlite-shm
Temporários de upload /var/lib/storage-api/tmp
JSON legado Desativado. O store oficial é somente SQLite.
Comandos perigosos em produção
Não use docker compose down -v, docker volume rm, docker volume prune ou docker system prune --volumes sem backup. Esses comandos podem apagar o volume onde ficam banco e arquivos.

Autenticação

Todas as rotas de arquivos exigem token de aplicação.

X-Storage-Token: SEU_TOKEN_DA_APLICACAO

Sem esse header, a API retorna 401. O token é gerado no painel administrativo. Guarde o token no backend principal ou em secret manager. Não coloque esse token no frontend.

Regras de path

Os paths são relativos à aplicação autenticada. A aplicação não informa o UUID no path.

Permitido Segmentos com letras, números, ponto, hífen e underline: a-z, A-Z, 0-9, ., _, -
Bloqueado .., ., path traversal, path vazio em operações obrigatórias e caracteres fora do padrão aceito.
Exemplos válidos products/images
tenants/4/catalog/products
branding/logo
Exemplos inválidos ../secret
products/../../x
produto imagem
tenants/4/logo@2x

Tipos de arquivo aceitos

A API valida a assinatura binária do arquivo, não apenas a extensão.

PNG image/png
JPEG/JPG image/jpeg
WEBP image/webp
PDF application/pdf

Arquivos fora desses formatos retornam erro de tipo não permitido.

Como enviar um arquivo

O upload é feito por multipart/form-data.

POST /api/files/upload
Autenticação Header X-Storage-Token obrigatório.
Content-Type multipart/form-data
Campo obrigatório file → arquivo enviado.
Campo obrigatório path → diretório relativo dentro da aplicação. Ex.: products/images
Campo opcional filename → nome final do arquivo. Se não for enviado, a API usa o nome original.
Limite Padrão atual de 10 MB. Configurável por MAX_UPLOAD_SIZE.
Exemplo de resposta 
{
  "success": true,
  "applicationId": "83d30cf4-3e30-4ed6-ae31-21d3f6cb02e4",
  "relativePath": "products/images/product-01.png",
  "sizeBytes": 58231,
  "mimeType": "image/png",
  "fileUrl": "http://localhost:3999/api/files/read?path=products%2Fimages%2Fproduct-01.png"
}

Como listar arquivos

Lista arquivos e diretórios de um caminho específico.

GET /api/files?path=products/images
Autenticação Header X-Storage-Token obrigatório.
Query obrigatória path → diretório relativo para listar.
Retorno Array de itens. Diretórios terminam com /.
Exemplo de resposta 
{
  "success": true,
  "items": [
    "category-a/",
    "banner-home.png",
    "product-01.jpg"
  ]
}

Como ler um arquivo

A API faz streaming do arquivo solicitado.

GET /api/files/read?path=products/images/product-01.png
Autenticação Header X-Storage-Token obrigatório.
Query obrigatória path → arquivo relativo dentro da aplicação.
Resposta Conteúdo binário do arquivo com Content-Type, Content-Length e Content-Disposition.
Uso recomendado Seu backend principal consome essa rota e devolve o binário ao frontend sem expor o token.

Como remover um arquivo

Remove o arquivo informado no path da aplicação autenticada.

DELETE /api/files?path=products/images/product-01.png
Autenticação Header X-Storage-Token obrigatório.
Query obrigatória path → caminho relativo do arquivo.
Resposta JSON simples confirmando a remoção.
Diretórios A API de aplicação não foi feita para exclusão recursiva de diretórios. Exclusão administrativa de diretórios deve ser feita pelo painel admin.
Exemplo de resposta 
{
  "success": true,
  "message": "Arquivo removido."
}

Área administrativa

Recursos internos para gerenciar aplicações, tokens, arquivos, diagnóstico e histórico.

Gerenciador de arquivos /admin/storage
Diagnóstico visual /admin/diagnostics-ui

Exclusão administrativa
Pelo painel admin é possível excluir arquivos, diretórios vazios e diretórios com conteúdo mediante confirmação recursiva. A raiz do storage não pode ser removida. Exclusões administrativas são registradas no histórico como ADMIN_DELETE.

Respostas de erro comuns

Use esta tabela para tratar erros no backend integrador.

400 Campo obrigatório ausente, path inválido, tipo de arquivo não permitido ou caminho que não corresponde ao tipo esperado.
401 Header X-Storage-Token ausente, token inválido ou sessão administrativa expirada.
404 Arquivo ou diretório não encontrado.
409 Diretório não vazio em exclusão administrativa sem confirmação recursiva.
413 ou 400 Arquivo excede o limite máximo permitido. O middleware de upload retorna mensagem específica para limite de tamanho.
500 Erro interno inesperado. Deve ser investigado nos logs do container.
Formato típico de erro 
{
  "success": false,
  "message": "Header X-Storage-Token é obrigatório."
}

Regras importantes

Esses pontos evitam erro de integração e problemas de segurança.

  • O campo do arquivo deve se chamar exatamente file.
  • O campo path é obrigatório no upload, listagem, leitura e exclusão.
  • O campo filename é opcional no upload.
  • O header X-Storage-Token é obrigatório em upload, leitura, listagem e exclusão.
  • O limite padrão atual é de 10 MB por arquivo, configurável por MAX_UPLOAD_SIZE.
  • Somente PNG, JPEG, WEBP e PDF são aceitos.
  • Não use token diretamente no frontend em produção.
  • Não armazene paths absolutos da máquina ou do container no banco da aplicação principal.
  • Armazene preferencialmente o relativePath retornado no upload.
  • Para leitura pública de imagens, use uma rota do backend principal como proxy.

TypeScript no backend

import fs from 'fs';
import FormData from 'form-data';
import axios from 'axios';

const STORAGE_BASE_URL = 'http://storage-api:3999';
const STORAGE_TOKEN = process.env.STORAGE_TOKEN;

async function uploadImage() {
  if (!STORAGE_TOKEN) {
    throw new Error('STORAGE_TOKEN não configurado.');
  }

  const form = new FormData();
  form.append('path', 'products/images');
  form.append('filename', 'product-01.png');
  form.append('file', fs.createReadStream('./product-01.png'));

  const response = await axios.post(`${STORAGE_BASE_URL}/api/files/upload`, form, {
    headers: {
      ...form.getHeaders(),
      'X-Storage-Token': STORAGE_TOKEN
    },
    maxBodyLength: Infinity
  });

  console.log(response.data);
}

uploadImage().catch(console.error);

Exemplo de proxy de leitura no backend

import express from 'express';
import axios from 'axios';

const app = express();

const STORAGE_BASE_URL = 'http://storage-api:3999';
const STORAGE_TOKEN = process.env.STORAGE_TOKEN;

app.get('/media/read', async (req, res, next) => {
  try {
    if (!STORAGE_TOKEN) {
      throw new Error('STORAGE_TOKEN não configurado.');
    }

    const relativePath = String(req.query.path || '');

    const response = await axios.get(`${STORAGE_BASE_URL}/api/files/read`, {
      params: { path: relativePath },
      headers: {
        'X-Storage-Token': STORAGE_TOKEN
      },
      responseType: 'stream'
    });

    res.setHeader('Content-Type', response.headers['content-type'] || 'application/octet-stream');
    res.setHeader('Cache-Control', 'public, max-age=3600');

    response.data.pipe(res);
  } catch (error) {
    next(error);
  }
});

Java

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.UUID;

public class StorageUploadExample {
    public static void main(String[] args) throws IOException, InterruptedException {
        String token = System.getenv("STORAGE_TOKEN");
        if (token == null || token.isBlank()) {
            throw new IllegalStateException("STORAGE_TOKEN não configurado.");
        }

        String boundary = "----StorageBoundary" + UUID.randomUUID();
        Path filePath = Path.of("product-01.png");
        byte[] fileBytes = Files.readAllBytes(filePath);

        String bodyStart =
            "--" + boundary + "\\r\\n" +
            "Content-Disposition: form-data; name=\\"path\\"\\r\\n\\r\\n" +
            "products/images\\r\\n" +
            "--" + boundary + "\\r\\n" +
            "Content-Disposition: form-data; name=\\"filename\\"\\r\\n\\r\\n" +
            "product-01.png\\r\\n" +
            "--" + boundary + "\\r\\n" +
            "Content-Disposition: form-data; name=\\"file\\"; filename=\\"product-01.png\\"\\r\\n" +
            "Content-Type: image/png\\r\\n\\r\\n";

        String bodyEnd = "\\r\\n--" + boundary + "--\\r\\n";

        byte[] startBytes = bodyStart.getBytes();
        byte[] endBytes = bodyEnd.getBytes();

        byte[] requestBody = new byte[startBytes.length + fileBytes.length + endBytes.length];
        System.arraycopy(startBytes, 0, requestBody, 0, startBytes.length);
        System.arraycopy(fileBytes, 0, requestBody, startBytes.length, fileBytes.length);
        System.arraycopy(endBytes, 0, requestBody, startBytes.length + fileBytes.length, endBytes.length);

        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("http://storage-api:3999/api/files/upload"))
            .header("X-Storage-Token", token)
            .header("Content-Type", "multipart/form-data; boundary=" + boundary)
            .POST(HttpRequest.BodyPublishers.ofByteArray(requestBody))
            .build();

        HttpClient client = HttpClient.newHttpClient();
        HttpResponse response = client.send(request, HttpResponse.BodyHandlers.ofString());

        System.out.println(response.body());
    }
}

JavaScript no navegador somente para teste local controlado

// Não use este exemplo em produção.
// Ele expõe o X-Storage-Token no navegador.

async function uploadImageForLocalTestOnly(file) {
  const form = new FormData();
  form.append('path', 'products/images');
  form.append('filename', file.name);
  form.append('file', file);

  const response = await fetch('http://127.0.0.1:3999/api/files/upload', {
    method: 'POST',
    headers: {
      'X-Storage-Token': 'SEU_TOKEN_APENAS_PARA_TESTE_LOCAL'
    },
    body: form
  });

  const data = await response.json();
  console.log(data);
}

<?php

$token = getenv('STORAGE_TOKEN');

if (!$token) {
    throw new Exception('STORAGE_TOKEN não configurado.');
}

$ch = curl_init();

$data = [
    'path' => 'products/images',
    'filename' => 'product-01.png',
    'file' => new CURLFile(__DIR__ . '/product-01.png')
];

curl_setopt_array($ch, [
    CURLOPT_URL => 'http://storage-api:3999/api/files/upload',
    CURLOPT_POST => true,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        'X-Storage-Token: ' . $token
    ],
    CURLOPT_POSTFIELDS => $data,
]);

$response = curl_exec($ch);

if ($response === false) {
    throw new Exception(curl_error($ch));
}

curl_close($ch);

echo $response;

Go

package main

import (
	"bytes"
	"fmt"
	"io"
	"mime/multipart"
	"net/http"
	"os"
)

func main() {
	token := os.Getenv("STORAGE_TOKEN")
	if token == "" {
		panic("STORAGE_TOKEN não configurado")
	}

	var requestBody bytes.Buffer
	writer := multipart.NewWriter(&requestBody)

	_ = writer.WriteField("path", "products/images")
	_ = writer.WriteField("filename", "product-01.png")

	fileWriter, err := writer.CreateFormFile("file", "product-01.png")
	if err != nil {
		panic(err)
	}

	file, err := os.Open("./product-01.png")
	if err != nil {
		panic(err)
	}
	defer file.Close()

	_, err = io.Copy(fileWriter, file)
	if err != nil {
		panic(err)
	}

	writer.Close()

	req, err := http.NewRequest("POST", "http://storage-api:3999/api/files/upload", &requestBody)
	if err != nil {
		panic(err)
	}

	req.Header.Set("Content-Type", writer.FormDataContentType())
	req.Header.Set("X-Storage-Token", token)

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Println(string(body))
}
